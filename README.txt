1. ЩО ЦЕ ЗА ДОДАТОК
================================================================================
Це веб-додаток (працює і як звичайний сайт, і як Telegram Mini App) для
організації дитячого табору. Він вирішує три задачі:

  • АДМІН завантажує Excel-таблицю зі списком дітей — система автоматично
    розбирає її, створює зміну (заїзд) і розкидає дітей по командах.
  • СУПРОВІД (вожатий) відмічає присутність своєї команди, редагує дані дитини,
    нараховує/списує "Айрон-долари", переводить дітей між командами.
  • ДИТИНА заходить, знаходить себе за ПІБ + номером команди, "прив'язує"
    свій профіль і бачить свій баланс Айрон-доларів.

Уся мова інтерфейсу — українська. Дизайн — темний, мобільний-перший
(вертикальний, під екран телефону в Telegram).

2. РОЛІ ТА СЦЕНАРІЇ ВИКОРИСТАННЯ
================================================================================

РОЛЬ: ДИТИНА (child)
  Вхід: вводить номер команди + повне ПІБ → сервер шукає збіг → підтверджує →
  профіль "прив'язується" (has_logged_in = true).
  Бачить: своє ім'я, команду, баланс Айрон-доларів, нотатки для себе.
  Не бачить: інших дітей, інші команди, службові дані.

РОЛЬ: СУПРОВІД (supervisor)
  Вхід: номер своєї команди + пароль "Супровід<номер>" (напр. Супровід2).
  Вкладки:
    • Команди     — список усіх команд; своя команда розгортається і редагується,
                    чужі — тільки для перегляду (замок).
    • Переводи    — перенесення дитини в іншу команду з історією.
    • Сповіщення  — стрічка подій (переводи, зміни балансу тощо).
  Може: відмічати присутність, редагувати дитину зі СВОЄЇ команди, нараховувати
  Айрон-долари, писати нотатки.
  Не може: видаляти дітей, змінювати чужі команди, керувати змінами.

РОЛЬ: АДМІН (admin)
  Вхід: команда 99 + STAFF_ADMIN_PASSWORD (секрет на бекенді).
  Вкладки:
    • Зміни      — створення зміни (назва, тип, дати) + завантаження Excel.
    • Статистика — по кожній зміні: дітей, команд, присутніх, увійшли, Айрон,
                   переводи; окремо "сироти" (діти без прив'язки до зміни).
    • База       — загальна кількість дітей/команд, список паролів супроводу,
                   повне очищення бази (небезпечна дія з підтвердженням).

3. ТЕХНОЛОГІЧНИЙ СТЕК
================================================================================
  Frontend : React 18 + TypeScript 5 + Vite 5
  Стилі    : Tailwind CSS 3 + tailwindcss-animate + семантичні CSS-токени
  UI       : shadcn/ui (Radix UI примітиви) — ~50 компонентів
  Іконки   : lucide-react
  Роутинг  : react-router-dom v6
  Дані     : @tanstack/react-query (провайдер підключено) + прямі запити Supabase
  Excel    : SheetJS (xlsx)
  Форми    : react-hook-form + zod + @hookform/resolvers
  Тости    : sonner + власний use-toast (Radix Toast)
  Графіки  : recharts (доступний, для статистики)
  Бекенд   : Lovable Cloud (PostgreSQL + Auth + Edge Functions на Deno)
  Тести    : vitest + @testing-library/react + jsdom
  Лінт     : eslint 9 + typescript-eslint

  ┌──────────────────────────────────────────────────────────┐
  │  Браузер / Telegram WebView                              │
  │  React SPA (один маршрут "/" з внутрішнім перемикачем)   │
  │     RoleSelect → ChildFlow | SupervisorFlow | AdminFlow  │
  └───────────────┬──────────────────────┬───────────────────┘
                  │ supabase-js          │ fetch (invoke)
                  ▼                      ▼
  ┌───────────────────────┐   ┌────────────────────────────────┐
  │  PostgREST (Data API) │   │  Edge Functions (Deno)         │
  │  + RLS-політики       │   │   • child-login                │
  │  таблиці: shifts,     │   │   • staff-login                │
  │  children, transfers, │   │   • _shared/accounts.ts        │
  │  notifications,       │   │  (працюють під service_role)   │
  │  uploaded_files,      │   └──────────────┬─────────────────┘
  │  user_roles           │                  │
  └───────────┬───────────┘                  │
              └──────────► PostgreSQL ◄──────┘
                           + schema private (SECURITY DEFINER хелпери)
                           + Supabase Auth (внутрішні технічні акаунти)

Ключова ідея безпеки: користувач НІКОЛИ не вводить справжні креденшели
Supabase. Edge-функція перевіряє "людський" пароль/ПІБ, і лише потім сама
створює технічний auth-акаунт і повертає готову сесію клієнту.

6. БАЗА ДАНИХ
================================================================================

shifts — заїзди/зміни
    id uuid PK | name text | shift_type ('long'|'short'|'international')
    start_date date | end_date date | is_active bool | team_offset int
    created_at | updated_at (тригер update_shifts_updated_at)

children — діти
    id uuid PK | shift_id uuid → shifts | row_number int (№ у таблиці)
    team_number int | full_name text | phone text | team_name text
    note_from_table text (примітка з Excel) | supervisor_notes text
    is_present bool | has_logged_in bool | iron_dollars int
    telegram_username text | raw_data jsonb (уся вихідна строка Excel)
    created_at | updated_at (тригер update_children_updated_at)

transfers — історія переводів
    id | child_id | child_full_name | from_team | to_team | performed_by |
    created_at

notifications — стрічка подій
    id | type | title | message | metadata jsonb | created_at

uploaded_files — журнал імпортів
    id | filename | shift_id | rows_count | created_at

user_roles — ролі (ОКРЕМА таблиця, ніколи не в профілі!)
    id | user_id → auth.users | role app_role ('admin'|'supervisor'|'child')
    team_number int | child_id uuid | UNIQUE(user_id, role)

Функція update_updated_at_column() + тригери на children і shifts автоматично
оновлюють updated_at.

7. БЕЗПЕКА
================================================================================
  • RLS увімкнено на всіх таблицях; без політики доступу немає взагалі.
  • Схема private НЕ експонується через API. У ній живуть SECURITY DEFINER
    функції: private.has_role(), private.is_staff(), private.my_child_id(),
    private.my_team(). anon не має EXECUTE на них.
  • children: персонал читає; супровід оновлює ЛИШЕ свою команду;
    видалення — тільки admin; дитина читає лише власний рядок.
  • shifts / notifications / transfers / uploaded_files: читання — персонал,
    зміни — адмін (крім вставки сповіщень і переводів персоналом).
  • user_roles: читання і будь-який запис — тільки адмін. Ролі ніколи не
    задаються з клієнта — тільки edge-функцією під service_role.
  • Пошук дитини повертає замасковані імена і максимум 3 результати —
    захист від "викачування" списку.
  • Порівняння паролів — constant-time.

  ВАЖЛИВЕ ЗАСТЕРЕЖЕННЯ: за поточним рішенням пароль супроводу — це
  "Супровід<номер команди>", тобто він легко вгадується. Це свідомий вибір
  зручності. Якщо потрібна реальна безпека — перейдіть на HMAC-коди
  (вони вже реалізовані як запасний шлях у staff-login).

8. АВТОРИЗАЦІЯ — ЯК ЦЕ ПРАЦЮЄ ПОКРОКОВО
================================================================================
  1. Користувач вводить "людські" дані (ПІБ або пароль команди).
  2. Клієнт викликає edge-функцію (child-login / staff-login).
  3. Функція під service_role перевіряє дані.
  4. issueSession() створює/оновлює технічний акаунт виду
     staff-team-2@ironhelp.local, staff-admin@ironhelp.local або
     child-<id>@ironhelp.local, з детермінованим паролем.
  5. Перезаписується рядок ролі в user_roles.
  6. Функція входить від імені цього акаунта і повертає session у JSON.
  7. Клієнт викликає supabase.auth.setSession(session) — далі всі запити
     проходять через RLS уже з правильною роллю.

10. ФОРМАТ EXCEL-ТАБЛИЦІ
================================================================================
  Перший аркуш книги. Рядок заголовків визначається автоматично.
  Розпізнавані колонки (регістр і зайві пробіли не важливі):
     Наявність / Присутність      → присутність (галочка)
     № / Номер                    → порядковий номер у таблиці
     № команди / Номер команди    → номер команди (обов'язково)
     ПІБ / ПІБ дитини / ФИО       → повне ім'я (обов'язково)
     Номер телефону / Телефон     → телефон (очищується до цифр і "+")
     Команда                      → назва команди
     Примітка / Примечание        → нотатка з таблиці
  Невпізнані колонки не втрачаються — вони йдуть у raw_data.
  Повторний імпорт того самого файлу не створює дублів: збіг шукається за
  ключем shift_id + team_number + нормалізоване ім'я + телефон.

12. ТИПОВІ ПРОБЛЕМИ
================================================================================
  «401 invalid_credentials» при вході супроводу
      Пароль має вигляд "Супровід2" (українською, без пробілу). Для адміна —
      команда 99 і пароль з секрету STAFF_ADMIN_PASSWORD.

  Список команд порожній
      Немає активної зміни або дітей у ній. Активність визначається ДАТАМИ,
      а не прапорцем is_active. Перевірте start_date/end_date зміни.

  Дитина не знаходить себе
      Потрібні і номер команди, і ПІБ (мінімум два слова, 6+ символів).
      Пошук іде тільки в межах указаної команди активної зміни.

  Дублі дітей після імпорту
      Дедуп працює за ключем shift+команда+ім'я+телефон. Якщо в таблиці
      відрізняється телефон або написання імені — рядки вважаються різними.

  Порожній екран / помилки прав у консолі
      Найчастіше — прострочена сесія. Вийдіть і зайдіть заново.
