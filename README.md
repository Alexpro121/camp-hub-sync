## 1. Що вміє система

| Модуль | Опис |
|---|---|
| Команди | Списки дітей, присутність, індикатор входу, картка дитини з нотатками |
| Айрон Долари | Атомарне нарахування/списання з повною історією транзакцій |
| Трансфери | Переведення дитини між командами та обмін «ПІБ на ПІБ» через захищені RPC |
| Розклад | Багатоденний імпорт через AI Studio, чернетки, публікація, таймлайн, підслоти по командах |
| Ярмарок | QR-оплата (Apple Pay-подібний сканер), друковані прайс-теги A4, каса супроводу |
| Потяг | Єдине статичне розселення по купе, ролі пасажирів, запити на обмін місцями |
| Таланти | Збір номерів від команд, автогенерація порядку виступів |
| Dynamic Island | Живі сповіщення (початок івенту, за 5 хв, оплати, обміни) з авто-приховуванням 6–12 с |
| Офлайн | IndexedDB + черга синхронізації, кеш React Query |
| Експорт | Вивантаження актуальної бази у `.xlsx` |

## 2. Технічний стек

- **Frontend:** React 18 + Vite 5 + TypeScript 5, Tailwind CSS 3, shadcn/ui, lucide-react
- **Стан/дані:** TanStack Query (+ persist), Supabase Realtime
- **Backend (Lovable Cloud):** Postgres + RLS, Edge Functions (Deno), Auth
- **AI:** Groq (`groq/compound`) для парсингу таблиць/купе + міст на Google AI Studio для розкладу
- **Інше:** jsQR (сканер), qrcode, xlsx/jszip (експорт), idb-keyval (офлайн), Telegram WebApp SDK

## 4. Ролі та вхід (покроково)

### Дитина
1. Головний екран → **«Я дитина»**.
2. Ввести **ПІБ** + **номер команди** → Edge Function `child-login` шукає збіг у активній зміні.
3. Успіх → профіль (тільки читання): баланс Айрон Доларів, розклад **лише на сьогодні**, купе, ярмарок, таланти.
4. Система позначає `has_logged_in = true` — супровід бачить зелений індикатор.

### Супровід
1. **«Я супровід»** → номер команди + пароль (за замовчуванням `Супровід<номер>`, напр. `Супровід3`).
2. Доступ: своя команда на редагування, інші — на перегляд.
3. Вкладки: Команди · Трансфери · Сповіщення · Банк Айрон Доларів · Каса Ярмарку (коли ярмарок активний) · Потяг · Таланти.

### Адміністратор
1. **«Я супровід»** → команда `99`, пароль `Adminlex`.
2. Анімація → секретна панель.
3. Зверху — **Active Shift Selector**: усі адмін-екрани миттєво перемикаються на обрану зміну (без перезавантаження).

## 5. Покроковий сценарій запуску зміни

1. **Створити зміну** в адмінці: тип (`long` 12 днів · `short` 5 днів · `international` · `sports` ⚡), дати, `team_offset`.
2. **Завантажити список дітей**: Excel/CSV або посилання на Google Sheets → `import-table` (AI-мапінг заголовків) → прев'ю → підтвердження. Дублікати відсіюються.
3. **Керувати командами** через теги команд (`TeamTagInput`) — жодних хардкодів.
4. **Імпортувати розклад**: «Імпорт розкладу через AI Studio» → вставити сирий текст → скопіювати згенерований промт → вставити відповідь-JSON → зберігається **як чернетка** → перевірити в редакторі → **«Опублікувати розклад»**.
5. **Розселення в потязі**: імпорт тексту (локальний парсер, AI як фолбек) → перевірка купе → `train_coupes_published` → діти бачать своє місце; за потреби ввімкнути обмін місцями.
6. **Ярмарок**: створити пресети товарів, роздрукувати A4-сітку 3×3 QR-кодів, відкрити касу.
7. **Вечір талантів**: створити подію → «Збір номерів» → команди подають → генерація порядку.
8. **Експорт** актуальної бази у `.xlsx` у будь-який момент.

## 6. Модулі системи

### Розклад
- Категорії: `fair`, `meal`, `sports`, `gathering`, `transfer`, `general` — кожна зі своєю іконкою та кольором рамки.
- Підслоти (`sub_slots`) для рознесеного харчування та колової системи станцій.
- Коректна обробка подій через північ, автоперемикання дати опівночі, злиття кількох розкладів (табір + зміна + команда).
- Нагадування: за 5 хвилин і на старті події через Dynamic Island.

### Ярмарок
- Дитина сканує QR (`ApplePayScannerModal`) або вводить 5-значний код вручну.
- Атомарна оплата `pay_fair_purchase` із захистом від подвійного сканування.
- Супровід бачить живий HUD платежів; після завершення — підсумковий режим.

### Потяг
- Одне статичне розселення на всю зміну (`SINGLE_TRIP = 1`).
- Ролі пасажирів: Учасник / Супровід / Спікер / Адміністрація.
- Запити на обмін: peer-to-peer, з авто-підтвердженням за налаштуванням зміни.

## 8. База даних

Таблиці: `shifts`, `children`, `transfers`, `notifications`, `uploaded_files`, `user_roles`,
`iron_dollar_transactions`, `schedules`, `schedule_items`, `talent_events`, `talent_entries`,
`broadcasts`, `train_coupes`, `coupe_swap_requests`,
`fair_settings`, `fair_payments`, `fair_short_codes`, `fair_preset_codes`.

Ключові RPC: `increment_iron_dollars`, `pay_fair_purchase`, `resolve_fair_code`,
`execute_child_transfer`, `execute_child_swap`, `execute_coupe_swap`,
`search_child_for_transfer`, `get_available_transfer_teams`.

Допоміжні security-definer функції живуть у приватній схемі: `private.has_role`, `private.is_staff`, `private.my_team`, `private.my_coupe_key`.

М'яке видалення: `deleted_at` у `shifts`, `children`, `schedules`.

## 9. Edge Functions та секрети

| Функція | Призначення |
|---|---|
| `child-login` | Вхід дитини за ПІБ + командою, повертає лише непрозорий ID |
| `staff-login` | Вхід супроводу/адміна, ідемпотентне створення акаунтів |
| `import-table` | Парсинг Excel/CSV/Google Sheets з AI-мапінгом заголовків |
| `parse-schedule-ai` | Резервний AI-парсинг розкладу (завжди HTTP 200 + локальний фолбек) |
| `parse-coupes-ai` | AI-фолбек для розселення в потязі |
| `_shared/groq-pool.ts` | Ротація ключів Groq, backoff на 429 |

Секрети (у бекенді, не в коді): `GROQ_API_KEY*`, `STAFF_SUPERVISOR_SECRET`.

## 10. Безпека

- RLS увімкнено на всіх публічних таблицях + явні `GRANT`.
- Ролі — окрема таблиця `user_roles`, перевірка через `private.has_role` (без ескалації привілеїв).
- Записи супроводу обмежені власною командою (`private.my_team`); адмін — виняток.
- Пошук дітей маскує ПІБ і обмежує кількість результатів.
- AI-функції захищені `requireUser()`.

## 12. Траблшутинг

| Симптом | Причина / рішення |
|---|---|
| `401 invalid_credentials` при вході супроводу | Невірний пароль — формат `Супровід<номер>`; адмін може переглянути коди в панелі |
| Вкладка «Ярмарок» не з'явилась | Статус підтягується протягом ~3 с після старту події; `useFairAccess` робить прогріви після логіну |
| Розклад не видно дітям | Розклад у чернетці — натисніть «Опублікувати розклад» |
| AI повернув битий JSON | `src/lib/json-sanitizer.ts` лагодить фенси/коми; при невдачі спрацьовує локальний парсер |
| Немає місця в потязі у дитини | Не встановлено `train_coupes_published` для зміни |
